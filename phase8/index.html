Multi-Layered Security

Detection Engine Architecture

GateKeeper uses a phased defense-in-depth framework to catch zero-day supply chain threats.

Phase 1 — Metadata Checker

PyPI API & Anomaly Analysis

Inspects package creation date, weekly download volume, author reputation, and homepage source code link validity.

PyPI REST API Metadata Heuristics
Phase 2 — Typosquatting Engine

Levenshtein Edit-Distance

Compares every requirement against the top 50 PyPI packages to catch subtle brand-jacking (e.g., reqeusts vs requests).

Levenshtein Distance Top 50 Packages
Phase 3 — Static AST Analysis

Abstract Syntax Tree Scanner

Parses setup.py into Python AST nodes to flag exec(), eval(), base64 payloads, subprocess calls, and credential exfiltration.

Python AST Static Analysis
Phase 4 — Docker Sandbox

Isolated Container Runtime

Executes installation inside an ephemeral container to monitor file modifications and outbound network calls during build time.

Docker Container Runtime Sandbox
Phase 5 — GitHub Action & SLSA

CI/CD Build Gatekeeper

Blocks automated pull requests if risk score exceeds policy thresholds and generates tamper-proof SLSA provenance reports.

GitHub Actions SLSA Provenance
Phase 6 — Benchmarking

Empirical Threat Intel

Validated against the open-source Backstabber's Knife Collection dataset of real PyPI malware samples.

Zero Friction Setup

Integrate into GitHub Actions in 60 Seconds

Add GateKeeper to your repository's workflow to automatically scan every pull request before dependencies are installed into your build agents.

  • Automated GitHub Security Report artifact generation
  • Zero external agent installation required
  • Configurable threshold blocking policies
.github/workflows/security.yml 
name: Security Audit Pipeline
on: [push, pull_request]

jobs:
  gatekeeper-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: GateKeeper Supply Chain Scan
        uses: Swan/gatekeeper@v1
        with:
          requirements-file: 'requirements.txt'
          fail-on-severity: 'CRITICAL'
          skip-sandbox: 'true'
